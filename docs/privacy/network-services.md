# Network services

Static source inventory, 2026-09-09. Entries marked inferred require packet/device confirmation; this is not a complete observed traffic allowlist.

| Domain / endpoint | Purpose | Data disclosed | Required? | Platform / evidence |
|---|---|---|---|---|
| `www.youtube.com/oembed` | Resolve video/playlist metadata | IP, requested media URL, client headers | For supported URL resolution | Both; OEmbedClient.swift / YouTubeSources.kt |
| `www.youtube.com/feeds/videos.xml` | Channel uploads; also „Neu bei deinen Kanälen“ (ADR 0001): newest uploads of channels already on the profile's whitelist with level „Vertrauenswürdige Reihe“ – iOS when the child home appears, Android at most every 30 min per channel while the app runs (results go to the local channel cache) | IP, channel ID, client headers | For channel refresh and the new-episodes row; no wish data is sent | Both; RSSFeedClient.swift (`channelFeed`) / ChannelFeedSource, `kid/KidNeueFolgen.kt` |
| `www.youtube.com/feeds/videos.xml?playlist_id=` | Playlist contents (first 15 entries) for a playlist the parents approved, when the child opens it; also the sleep playlist on iOS. Each entry names its own channel ID; results go to the local cache under `playlist:<id>` | IP, playlist ID (URL-encoded), client headers | For approved playlists; no key, no quota. iOS continues with the Data API only if a key is configured | Both; RSSFeedClient.swift (`playlistVideos`) / PlaylistFeedSource |
| `www.youtube.com/channel`, `/@`, `/c` | Channel metadata scraping | IP, channel/handle, configured User-Agent | Current fallback; provider-policy review needed | Both; ChannelPageClient.swift / ChannelPageSource |
| `www.googleapis.com/youtube/v3` | Optional Data API | IP, API key, media IDs/search parameters | Optional | iOS; YouTubeDataAPIClient.swift. Android key setting has no matching client |
| `www.youtube.com/iframe_api` | Load player script | IP, client and referring origin | YouTube playback | Both HTML players |
| `www.youtube-nocookie.com` | Privacy-enhanced player | IP, media ID, client/referrer and playback context | iOS and Android YouTube players | iOS Player.html, Android player.html |
| `www.youtube.com` | IFrame API script; no longer the Android embed host | Above; third-party cookies still accepted on Android, cleared at session start and teardown | Both players | iOS Player.html, Android player.html and PlayerBridge.kt |
| `i.ytimg.com` | Video thumbnails | IP, video ID, client headers | Visible images; placeholder otherwise | iOS image loaders; Android `Vorschaubilder` loads only from a fixed allowlist (`i.ytimg.com`, `yt3.ggpht.com`, `yt3.googleusercontent.com`) in kid lists, channel view and header, parent lists, review dialog and add preview |
| `yt3.ggpht.com`, `yt3.googleusercontent.com` and returned thumbnail hosts | Channel images | IP, image path, client headers | Image display only; Android also fetches the channel page (`www.youtube.com/channel/<id>`) once per app start for channels without an image (kept in memory only) | iOS: provider-returned URLs; Android: fixed allowlist, see above |
| `*.googlevideo.com`, `*.gstatic.com`, other Google infrastructure | Media/CDN/player resources | IP, media/client/session context | Inferred provider dependencies | WebView traffic; exact hosts not measured |
| Allowlisted PeerTube hosts, e.g. `framatube.org` | API, embed, images/media | IP, requested video/channel, headers and possible remote-script data | Only selected PeerTube use | iOS PeerTubeClient/Bridge; no Android implementation |
| Federated PeerTube origin/CDN URLs | Returned media and image resources | As above | Depends on instance | Must verify that federation/redirects cannot escape the intended trust boundary |
| Parent-entered Nextcloud server: `POST <server>/ocs/v2.php/apps/spreed/api/v1/bot/<conversation>/message` | Optional parent notification of a new wish ([ADR 0005](../adr/0005-eltern-ueber-wuensche-benachrichtigen.md)); also „Test senden“ in the parent settings | IP, time, conversation token, HMAC signature and random value, message text „@<parents> SideTube: neuer Wunsch (N offen)“ – no child name, topic or title | Only when parents set it up; HTTPS only, no redirects followed, no cache/cookies, one attempt, 15 s timeout | Both; `ParentNotifier.swift` (`URLSessionPoster`) / `core/elternkanal/Elternmelder.kt` (`UrlConnectionPoster`) |
| `sidekids.github.io`, `github.com` | Parent-initiated project/support/privacy links | Browser request data | Optional | iOS Brand/About; verify public pages actually cover SideTube |

Native build-time dependencies contact Google Maven, Maven Central, Gradle distribution servers and GitHub; these are not app runtime services. No remote font, analytics or remote-config SDK was found in native dependency declarations.

Validation: capture clean-install idle, image browsing, first play, pause, stop, background, provider errors and consent states on both platforms. Record host, request purpose, cookie/storage behavior and sanitized headers. Keep raw traces private; do not place child history or API keys in this document.

YouTube states that loading an embedded player shares basic user data and requires appropriate child-directed handling. Review its [developer policies](https://developers.google.com/youtube/terms/developer-policies), [required functionality](https://developers.google.com/youtube/terms/required-minimum-functionality) and [embedding guidance](https://support.google.com/youtube/answer/171780?hl=en). Privacy mode alone does not satisfy child-directed designation requirements.
